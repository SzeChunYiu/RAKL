# Paper III Track A — objective known-answer benchmark: preregistration v1

Status: `REGISTRATION_ONLY / NO_ITEMS_GENERATED / NO_OUTCOME_ACCESS`
Refs #444, #442, #248. Supersedes nothing; the v2.1 n=16 packet remains
historical pilot evidence and **must not** become the confirmatory epoch by
having labels added after the fact.

This document is frozen **before** the generator exists. That ordering is the
point: the circularity control (§3) and the sample size (§4) both have to be
fixed before any outcome is visible, and the generator is exactly where the
temptation to adjust them appears.

Nothing here claims a result. It claims only what will be measured and what
would falsify it.

---

## 1. Claim being targeted

Claim **B** of #444 — objective machine-verifiable transfer discrimination.
No human annotators are required, and their absence does **not** block this
claim; it blocks only claim C (natural-domain external-human validity), which is
scoped as declared future work.

The estimand is explicitly **not** "can a classifier reproduce a rubric whose
structural coordinates were supplied by the same annotator". It is:

> Does RAKL-computed directional structure add information **beyond** semantic
> and content similarity about whether a proposed transfer is valid for the
> target context and QoI?

Incremental and paired. `STRUCTURE_ONLY` beating chance is not the claim.

---

## 2. Ground-truth rule (the thing that makes this independent without humans)

**A label is assigned by executing a verifier on the target instance. Never by
recording which coordinate the generator perturbed.**

This single rule is what makes the ground truth independent *by construction* —
a stronger guarantee than two annotators agreeing, because the label comes from
the world rather than from the same rubric that supplies the features.

Operationally, for every item:

1. the generator produces a source object, a candidate source→target map, and a
   target context/boundary/QoI;
2. the transfer is **executed or decided** against the target instance;
3. the verifier's outcome assigns `ACCEPT` / `REJECT` / `CANNOT_CHECK`, together
   with a proof, countermodel or execution trace as the witness.

Perturbation is how coverage of the space is obtained. It is **not** how truth is
assigned. Any code path that writes a decision from the perturbation identity is
a hand-labelled item and is disqualifying.

### 2.1 Prohibited by this registration

- writing `REJECT` because the generator knows it broke the boundary;
- deriving the decision from the item type, family name, or seed;
- back-filling a coordinate for completeness after outcome access
  (`UNKNOWN` / `CANNOT_CHECK` is retained instead).

---

## 3. Circularity control — the coordinate-ablated twin

**This is the primary falsifier and the main risk to the whole track.**

If invalidity is generated by breaking coordinate *X*, and the witness extractor
reports coordinate *X*, then `STRUCTURE_ONLY` wins by construction: the generator
wrote the answer and the witness reads it back. That would be the same
self-grading defect this repository has now hit six times, except published as
the headline result.

**Control.** Every confirmatory run is accompanied by a *coordinate-ablated
twin*: an item set in which the perturbation used to induce invalidity is **not**
among the coordinates the extractor reports.

| Outcome on the twin | Reading |
|---|---|
| `STRUCTURE_ONLY` still improves on `SEMANTIC_ONLY` | the signal is real |
| improvement collapses | the primary result measured the generator, and is reported as such |

The twin is run **before** any Δ is reported. A collapse is a first-class result
and is published as a negative finding, not repaired by regenerating items.

### 3.1 Semantic decorrelation

`SEMANTIC_NEAR_MISS_INVALID_TRANSFER` is not one item type among several — it is
the load-bearing stratum. If invalid items are also lexically distant, a BM25
control gets the answer for free and the measured Δ is lexical distance, not
structure.

Registered requirement: within each family, the distribution of semantic
similarity between source and target must be **statistically indistinguishable**
across `ACCEPT` and `REJECT` items, checked before outcome access. Items are
regenerated until this holds, and the check is reported.

## 4. Power — computed here, not inherited

Paired-difference sizing, α = 0.05 two-sided, power = 0.80, registered
`MDE = 0.05` on paired Brier:

```text
n = (z_0.975 + z_0.80)^2 * sigma_d^2 / MDE^2 = 7.8489 * sigma_d^2 / 0.0025
```

| `sigma_d` | required n |
|---:|---:|
| 0.100 | 32 |
| **0.1236** | **48** |
| 0.150 | 71 |
| 0.200 | 126 |
| 0.250 | 197 |
| 0.300 | 283 |

**The prior ~n=48 figure is adequate only if `sigma_d <= 0.1236`.** That is a
tight assumption for a paired Brier difference on binary outcomes, and it was
inherited rather than verified. It is recorded here as an assumption, not a
result.

Every figure in this table is reproduced by `scripts/paper3_track_a_power.py`
(machine-readable copy: `research/paper3/PAPER3_TRACK_A_POWER_V1.json`), so the
arithmetic is checkable rather than asserted.

### 4.1 Discriminating items, not total items

#449 established on the v2.1 packet that the binding constraint is not total
items but items that can *distinguish the arms*. Items where both arms make the
same prediction contribute `d_i = 0` and dilute the mean difference.

With `q` = fraction of items on which the semantic and structural arms diverge:

| `q` | items needed for 48 discriminating |
|---:|---:|
| 1.00 | 48 |
| 0.50 | 96 |
| 0.30 | 160 |
| 0.188 | 256 |

`q` is **not** the same quantity as the v2.1 decoupling rate (which compares the
label to `AND(witnesses)`, not one arm to another), and it is not assumed here.

**Registered procedure:** `q` and `sigma_d` are estimated on a disjoint
development set generated from the same families, before the confirmatory set is
generated and before any confirmatory outcome is accessed. The confirmatory `n`
is then computed from those estimates using the formula above and recorded in an
amendment to this document. If the required `n` exceeds what can be generated,
that is reported as an underpowered study rather than absorbed by lowering the
MDE.

### 4.2 Per-stratum minima

A packet-level count hides strata that contribute nothing — #449 found the
`matching_allocation` family contributed **zero** decoupled items, making one of
four leave-one-family-out folds uninformative by construction.

Registered: **each family × each item type must contain at least 4 items, and
each family must contain at least 4 discriminating items.** A stratum below
either floor is reported as underpowered for that stratum; the overall result is
not reported as if the stratum had been tested.

Both minima are fixed here, before generation. They are not to be revised after
seeing the realised rates.

## 5. Scope for v1

Ten families and nine item types is a quarter of work, not a study. Family
diversity exists to rule out a single-structure artifact; three heterogeneous
families with an executable verifier achieve that.

**Families (3), chosen for verifier exactness and structural distance:**

| Family | Verifier | Why |
|---|---|---|
| finite graph flow / cut / matching | exact max-flow = min-cut | combinatorial; the documented Ford–Fulkerson → Boykov graph-cuts transfer anchors it |
| logical entailment + countermodel pairs | decidable; countermodel is the witness | symbolic/deductive; high-surface-similarity near-misses are easy to construct |
| unit / coordinate transforms with exact invariants | dimensional consistency check | algebraic/dimensional; structurally distant from both above |

**Item types (5), chosen for discrimination rather than coverage:**

`VALID_DISTANT_TRANSFER`, `SEMANTIC_NEAR_MISS_INVALID_TRANSFER`,
`DIRECTION_REVERSED_INVALID`, `BOUNDARY_QOI_MISMATCH`,
`PARTIAL_MAPPING_REQUIRES_CANNOT_CHECK`.

The remaining four #444 types are coverage and are deferred; deferral is recorded
as a scope limitation, not as a completed item.

## 6. Anti-degeneracy battery — run before any candidate arm

All of the following must **fail** the joint metric vector. Any that succeeds
disqualifies the packet, and the packet is regenerated rather than the attack
weakened.

| Attack | Implementation |
|---|---|
| ID-only responder | `probe_blind_responder` over opaque item ids |
| always `ACCEPT` | constant responder |
| always `REJECT` | constant responder |
| always `CANNOT_CHECK` | constant responder |
| semantic-keyword heuristic | keyword responder over visible text |
| family-name heuristic | responder reading only the family label |
| copy-visible-invariant heuristic | responder echoing the visible invariant field |

Additionally, from the harness in `src/rakl/degeneracy_probe.py`:

- `probe_decoupling` with `min_decoupled` **and** the per-stratum minimum frozen
  by §4.2 before generation;
- `probe_arm_answer_leak`, treating the visible item as the treatment arm and the
  hidden truth store as gold — no visible field's token set may reproduce the
  gold decision;
- `probe_single_feature` and `probe_boolean_combination` over the visible fields.

### 6.1 The paraphrase blind spot

Token overlap does **not** detect semantic restatement. An objectively generated
packet can still encode the answer in a *paraphrase* — for example a template
that phrases invalid cases differently from valid ones.

Mitigation, registered: visible text is generated from a **single template per
family**, with the valid/invalid difference living only in the structural
content. Per family, template-derived features alone must not predict the label,
and this is asserted before outcome access.

A planted-degenerate twin is run alongside, and the no-alarm case on the clean
packet is asserted — a battery that fires on everything is switched off, and one
that fires on nothing is the defect it hunts.

---

## 7. Blinding

The candidate system never sees: the gold decision, the verifier witness,
answer-bearing family labels, or outcome-semantic identifiers. Item ids are
opaque and randomized; the hidden truth store is a separate artifact from the
visible packet.

---

## 8. Arms and comparators

Arms: `SEMANTIC_ONLY`, `STRUCTURE_ONLY`, `SEMANTIC_PLUS_STRUCTURE`,
`SEMANTIC_THEN_WITNESS_GATE`.

Controls per #444 Track C: `C0` lexical/BM25, `C1` historical BGE reranker,
`C2` strongest feasible current semantic reranker.

**Comparator selection is label-blind.** `C2` is chosen using external
general-purpose retrieval benchmarks or the disjoint development set — never by
picking whichever comparator loses most on the confirmatory outcomes. The
selection rule and the chosen comparator are recorded before confirmatory runs.

## 9. Reported quantities

Primary: `Delta Brier = Brier(semantic) - Brier(hybrid/witness)`, paired, against
the registered MDE.

Secondary, all reported regardless of sign: ROC-AUC, average precision, log loss,
calibration error, exact `ACCEPT`/`REJECT`/`CANNOT_CHECK` accuracy,
`VALID_DISTANT` true-accept rate, `SEMANTIC_NEAR_MISS` false-accept rate,
boundary/QoI error, wrong-direction error.

Abstention scoring is fixed here: `CANNOT_CHECK` is scored as a distinct third
outcome, not as a wrong answer and not as a free pass.

## 10. Freeze list (Track B)

Before confirmatory generation: extractor code revision, model identity, tool
policy, prompt/template hashes, resource ceiling, coordinate schema, abstention
semantics. Recorded with SHA-256 in the amendment alongside the `n` computation.
