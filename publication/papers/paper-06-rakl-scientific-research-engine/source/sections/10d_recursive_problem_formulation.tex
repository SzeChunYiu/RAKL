\section{From problem solving to recursive problem formulation}
\label{sec:recursive-problem-formulation}

A scientific research engine should not assume that the first textual statement of an unfamiliar
problem already supplies the correct scientific question or representation. Orion therefore
distinguishes a problem request from the active, versioned formulation used for pursuit. Before
committing to a question, framework or decomposition, it can compare registered alternatives under
a frozen decision contract, evidence cutoff and evaluator. The resulting formulation remains
non-sovereign: reframing may change what the engine searches for, but it cannot rewrite previously
observed evidence or mint scientific authority.

The capstone experiment consequently evaluates two coupled abilities. The first is
\emph{recursive formulation}: on fresh unfamiliar tasks, can the system identify when the question,
framework, decomposition, interface, measurement or evaluator is the responsible failure surface,
while avoiding gratuitous reframing on well-posed controls? The second is
\emph{governed self-improvement}: after a weakness is measured under a fixed evaluator epoch, can
the system assimilate or construct the smallest justified method challenger and improve on disjoint
fresh tasks without weakening the ruler authorizing the comparison?

This design separates outcomes a single success score would conflate: correct task solution,
correct abstraction-level diagnosis, false-reframe harm, audit cost, and fresh method-evolution
gain. A static framework or simpler reasoning-router parent may therefore be sufficient even when
the full system is operational. Such outcomes narrow the architecture rather than being relabeled
as failures of evaluation.

\subsection{Empirical axis}
\label{sec:recursive-formulation-epochs}

The capstone runs in two epochs. \textbf{Epoch A} (unfamiliar problem solving) compares a direct
solver, static Orion, generic self-reflection, a reasoning-structure/router parent, a
downward-recursion parent, and full recursive-formulation Orion on fresh unfamiliar tasks,
including well-posed controls on which any reframing is harmful waste. \textbf{Epoch B}
(governed self-improvement) uses Epoch A only as development evidence: one measured weakness and
one smallest justified challenger are frozen, then tested on disjoint fresh tasks under the same
evaluator epoch. Arms, families, cost accounting, hard gates and terminal vocabulary for both
epochs are fixed in the RFC-v1 benchmark design, which must be re-frozen on the implementation
subject before any utility execution; the committed known-world conformance result is instrument
evidence only.

The terminal vocabulary is preregistered so that the outcomes which would narrow this architecture
are named before the evidence rather than selected after it. Besides
\texttt{RECURSIVE\_FORMULATION\_RESIDUAL\_SUPPORTED}, the admissible terminals are:

\begin{itemize}[leftmargin=2em]
  \item \texttt{STATIC\_FRAMEWORK\_SUFFICIENT}\\
        the static parent matches the full system;
  \item \texttt{REASONING\_ROUTER\_PARENT\_SUFFICIENT}\\
        \texttt{DOWNWARD\_RECURSION\_PARENT\_SUFFICIENT}\\
        an existing parent already captures the effect;
  \item \texttt{FORMULATION\_HELPFUL\_ONLY\_ON\_INJECTED\_CASES}\\
        the gain does not survive outside constructed defects;
  \item \texttt{FALSE\_REFRAME\_HARM}\\
        reframing costs more than it returns on well-posed controls;
  \item \texttt{META\_OVERFIT}, \texttt{BENCHMARK\_INVALID}, \texttt{UNDERPOWERED},
        \texttt{CANNOT\_CHECK}.
\end{itemize}

Each parent-sufficiency terminal is a result this paper would report and absorb, not a failure to
be re-described: a parent that already explains the effect narrows the contribution to whatever
measurable residual survives it, and an invalid benchmark is never counted as a solver failure.
