# Evidence-Governed Method Assimilation

Status: supporting method layer v0.1. This document does not change the Constitution and does not authorize automatic installation or activation of external methods.

## 1. Purpose

RAKL should learn from external scientific-research systems without treating whole frameworks as indivisible competitors and without inheriting unsupported authority claims.

The assimilation pipeline is:

```text
broad external discovery
-> atomic method decomposition
-> ontology / interface normalization
-> semantic equivalence deduplication
-> authority decontamination
-> compatibility / obstruction analysis
-> explicit transition mapping into a RAKL fiber
-> frozen shadow evaluation
-> narrow promotion by the existing self-RAKL gate
-> residual monitoring and supersession history
```

The important unit is an **atomic method operator**, not a repository name.

## 2. External methods as local charts

An external method operator is a local chart of the meta-object:

> how should this atomic scientific-research step be performed?

For operator `m`, RAKL records a contract containing:

```text
component identity and source version
input and output schema
target RAKL fiber
context scope
assumptions
provenance and dependencies
failure modes
benchmark identity
authority it may mint
authority it must not mint
transition-map identity
```

A framework may contribute different operators to different fibers. Retrieval, hypothesis generation, formal checking and paper writing are therefore not glued merely because they live in one repository.

## 3. Authority decontamination

External success is not imported as scientific authority.

A method may produce a strong artifact while still lacking authority for a stronger claim. Examples:

```text
retrieved citation       != atomic claim support
predictive success       != mechanism identification
formal validity          != empirical truth of premises
agent consensus          != independent evidence
world-model memory       != canonical knowledge
many citations           != many independent evidence lineages
```

Each operator receives an authority envelope:

```text
may_mint
must_not_mint
```

Any requested authority outside the verified envelope is rejected before shadow testing.

## 4. Explicit transition witnesses

A useful external operator is not considered assimilated merely because its output looks compatible with a RAKL input.

RAKL requires an explicit transition witness:

\[
T_{m\rightarrow f}: O_m \rightarrow I_f,
\]

where `O_m` is the external operator output and `I_f` is the target fiber input contract.

The witness states what representation changes, units, assumptions, scopes, provenance or authority labels are preserved or transformed.

Missing transition evidence yields `CANNOT_CHECK`; refuted transition evidence yields `BLOCK`.

Round 012 similarity research independently showed that an explicit mapping may still be scientifically weak if the admissible mapping family is made arbitrarily flexible after seeing the desired pair. That observation is **not activated in v0.1** because the current assimilation benchmark was frozen before that child question was introduced. It is recorded for a separate transition-verification fiber that must freeze its own hostile worlds.

## 5. Three non-active outcomes before shadow testing

Normalization can terminate without multiplying the active method portfolio.

### Equivalent to incumbent

If the operator is semantically equivalent to an incumbent operator under the registered consumer and scope, it becomes corroboration / provenance rather than a second independent method count.

### Parallel local view

If the operator is locally valid but does not glue to the incumbent under current assumptions or context, RAKL preserves it as a parallel local method view. Incompatibility is not a reason to force one global workflow.

### Rejected or blocked

Known anti-patterns, forbidden authority escalation, refuted transitions or failed frozen gates remain negative method history.

## 6. Shadow eligibility is not activation

`ELIGIBLE_FOR_SHADOW` means only that a candidate is well-specified enough to face a frozen comparison.

The assimilation layer never returns `ACTIVE` and never moves `main`. Actual activation remains governed by the existing Class-A/Class-B promotion rules, blocking meta-QoIs and protected evaluator boundary.

## 7. Relationship to current external work

Current 2026 agent-skill work substantially narrows the novelty envelope.

- **SkillOps** already represents skills with typed contracts and maintains skill ecosystems across compatibility, utility, validation and risk.
- **SkillFoundry** converts heterogeneous scientific artifacts into validated skills with scope, I/O, environment assumptions, provenance and tests, then expands, repairs, merges or prunes the library.
- **HASP** turns skills into executable program functions and studies validated skill evolution.
- **SkillSmith** jointly evolves skills and tools, models complementarity/conflict and preserves anti-patterns with failure signatures and remedies.
- **S1-NexusAgent** performs dynamic scientific-tool retrieval and distills successful trajectories into reusable scientific skills.
- **Scientific Agent Skills** demonstrates versioned, portable scientific skill packages and supply-chain/provenance practices.
- **nature-skills** contributes small routed modules, multi-source fallback, deduplication, read-only raw archives and explicit review boundaries.

RAKL therefore does **not** claim invention of modular skills, typed skill contracts, skill evolution, dynamic tool routing, provenance or anti-pattern memory.

The candidate contribution is narrower: scientific-method operators are assimilated through a contextual Knowledge Atlas with explicit transition witnesses and a scientific authority envelope, while incompatible local methods remain visible and activation remains externally governed.

## 8. Executable support module

`src/rakl/assimilation.py` implements a support-only evaluator with outcomes:

```text
ELIGIBLE_FOR_SHADOW
EQUIVALENT_TO_INCUMBENT
PARALLEL_LOCAL_VIEW
BLOCK
REJECT
CANNOT_CHECK
```

It intentionally has no `ACTIVE` verdict.

## 9. Next empirical discriminator

The next RAKLBench lane should instantiate real operators from multiple frameworks under a matched task packet and compare:

```text
uncontrolled component aggregation
static curated pipeline
RAKL authority-preserving contextual assimilation
```

Primary failure metrics should include:

```text
cross-axis authority leakage
false method duplication
forced-fusion errors
negative-history resurrection
invalid transition acceptance
method value / cost after matched evidence and tool budgets
```

If an untyped import flag matches the typed contract on the frozen hostile worlds and downstream real-component trials, the additional assimilation structure does not earn runtime complexity.
