# VTG Ten-Round Adversarial Closure Audit — 2026-08-13

Status: `TEN_ROUND_BOUNDED_ADVERSARIAL_AUDIT_COMPLETE / NO_NEW_TOP_LEVEL_PLANE_FOUND / SIX_CROSS_CUTTING_OBLIGATIONS_ADDED`.

This audit performs ten independent hostile passes over Verified Transformation Geometry (VTG) and the surrounding Orion problem-solving theory. The objective is not to produce more terminology. A round contributes a new object only when it exposes a counterexample or theorem obligation that the current framework cannot already express safely.

## Final summary

The four-plane Orion architecture remains intact. The ten rounds did **not** expose another missing top-level solver plane. They did expose six cross-cutting obligations that should be added to the mathematical theory/preregistration:

1. **Geometry nontriviality / constructibility.** Bare existence of a greedily navigable geometry is too weak and can be vacuous.
2. **Operational-edge assurance classes.** Lean tactic-state transitions and kernel-certified mathematical derivations are not the same kind of edge.
3. **Learned-geometry support / identifiability.** A geometry trained only on policy-induced trajectories cannot infer unseen reachability without coverage or structural assumptions.
4. **Reachability quantifier semantics.** Existential path, controllable policy, robust-for-all-outcomes and almost-sure reachability are different claims.
5. **Concrete–abstract semantics for over-approximation.** Exact quotients and abstract/refinement systems need different contracts.
6. **Global amalgamation.** Pairwise/local compatibility of solved sections is not sufficient for a globally valid proof/solution object.

Several additional findings sharpen existing obligations rather than adding objects: enriched/path-algebra semantics, certified higher cells beyond simple commutation, navigation basins/domains of attraction, computability/complexity profiles, and compact/succinct routing tradeoffs.

No full polygraph/omega-category implementation is required for V0.

# Round 3 — Abstract interpretation / refinement / bisimulation

**Question:** Does a safe semantic quotient automatically preserve solver reachability?

**Result:** `A — FORMAL CONTRACT EXTENSION REQUIRED`.

The existing `NavigationQuotientValidation` closes the exact-quotient case, but the theory should distinguish two objects:

## Exact quotient

A map

\[
q:X\to \bar X
\]

with target preservation and suitable two-way simulation/route-lifting obligations.

## Over-approximating abstraction

An abstraction/concretization pair or relation

\[
\alpha:X\to \bar X,
\qquad
\gamma:\bar X\to \mathcal P(X)
\]

with

\[
x\in\gamma(\alpha(x))
\]

and a sound transition relation.

An abstract route may be spurious. It must be concretized/replayed or trigger refinement.

**New rule:** never call an over-approximating abstraction an exact navigation quotient.

# Round 4 — Directed geometry, greedy embeddings, compact routing

**Question:** Is “there exists a locally navigable geometry” a meaningful hypothesis?

**Result:** `A — MAJOR NONTRIVIALITY GAP FOUND`.

## Oracle-geometry trivialization theorem

For any finite connected unweighted graph \(G\) and target \(t\), define

\[
h_t(v)=d_G(v,t).
\]

For every non-target vertex \(v\), a shortest path gives a neighbor \(u\) with

\[
h_t(u)=h_t(v)-1.
\]

Thus exact target distance is a well-founded local navigation function and greedy descent reaches \(t\).

Therefore the existence question

> “Does a geometry exist in which local descent solves the graph?”

is nearly vacuous if the geometry constructor is allowed to perform global shortest-path computation or encode a large routing table first.

Greedy-embedding and compact-routing theory similarly show strong tradeoffs among embedding power, label size, local storage, query time and stretch.

## Required new object: GeometryNontrivialityContract

Every VTG geometry should report at least:

```text
construction_time / compute
construction_verifier_cost
coordinate_or_label_bits_per_state
global_auxiliary_storage
local_distance_query_cost
local_next_action_query_cost
target_dependence
access_to_gold_route_or_gold_distance
reuse_scope_and_expected_queries
invalidation/staleness horizon
route stretch / solve-cost stretch
fresh-family transfer
```

The scientific hypothesis becomes:

> A verifier-induced geometry is useful only if its **total construction + storage + local routing + verification cost** is lower than strong search controls in the registered reuse regime, without hidden test-route access.

Existence alone is not a contribution.

# Round 5 — Control theory / navigation functions / dynamic programming

**Question:** What exact theorem corresponds to “gravity points toward the solution”?

**Result:** `B — EXISTING WELL-FOUNDED DESCENT SHOULD ADD A BASIN CONTRACT`.

A navigation/Control-Lyapunov view shows that a descent function is meaningful only on a domain where a legal stabilizing action exists and spurious minima are excluded or explicitly characterized.

Define a **Certified Navigation Basin** \(S\):

```text
registered subject/operator basis/representation
every non-goal state has at least one verified admissible progress action
rank/value validity conditions hold on S
boundary/escape behavior is specified
all reachable minima satisfy the goal condition
```

The strongest discrete theorem remains the well-founded-rank result already in the closure audit.

A geometry may have useful basins without being globally navigable.

# Round 6 — Proof complexity / computability

**Question:** Could exact proof distance be assumed computationally available?

**Result:** `A — COMPLEXITY/COMPUTABILITY PROFILE REQUIRED`.

Proof search is not generically cheap. Near-shortest proof automation is hard in major proof systems, and sufficiently expressive theoremhood is undecidable.

Therefore every geometry must declare a **constructibility class**:

```text
EXACT_FINITE_ENUMERATION
POLYNOMIAL_CONSTRUCTION_IN_REGISTERED_CLASS
FIXED_PARAMETER_CONSTRUCTION
AMORTIZED_PRECOMPUTATION
APPROXIMATE_LEARNED
ORACLE_EVALUATOR_ONLY
UNCOMPUTABLE_OR_UNKNOWN_IN_GENERAL
```

The paper must separate:

\[
\text{existence of an exact cost-to-go function}
\]

from

\[
\text{efficiently constructing/querying that function}.
\]

Representation/operator changes may yield enormous proof-complexity speedups; this strengthens, rather than weakens, the need to bind geometry to the proof calculus/operator basis.

# Round 7 — Lean/proof-assistant operational semantics

**Question:** Is every tactic-state edge a kernel-certified mathematical transition?

**Result:** `A — EDGE ASSURANCE CLASSES REQUIRED`.

Lean tactics operate over environment, metavariable context and goal state. Intermediate tactic-state transitions are metaprogramming operations; the final assembled proof term/declaration is checked by the kernel.

Therefore define:

```text
KERNEL_DERIVATION_EDGE
    local proof-carrying derivation whose mathematical validity is independently checkable

REPLAY_VALIDATED_OPERATIONAL_EDGE
    exact-snapshot / exact-tool-version tactic transition reproducibly replayed
    proposal/search authority only

CANDIDATE_OPERATIONAL_EDGE
    proposed but not replay validated
```

The operational state identity should bind all future-relevant state, including at least:

```text
environment/library hash
Lean/kernel/elaborator/tactic versions
local context
goals/metavariables/assignments
relevant options
representation/operator basis
random seed/external nondeterminism where applicable
```

**Authority rule:** replay-valid tactic edges may support navigation; the final proof constellation receives mathematical authority only through the ordinary audited proof receipt/kernel check.

# Round 10 — Learned geometry, identifiability, data coverage

**Question:** Can a geometry learned from past search trajectories infer true reachability outside the visited support?

**Result:** `A — GEOMETRY-LEARNING COVERAGE RECEIPT REQUIRED`.

## Support-indistinguishability argument

Let two true transition systems \(G_1,G_2\) agree on every state/edge present in training data \(D\), but differ on an unobserved shortcut/bridge.

Any deterministic geometry learner receiving only \(D\) produces the same output on both worlds, yet the exact target cost-to-go differs.

Therefore exact reachability geometry is **not identifiable from insufficient support without additional structural assumptions or exploration**.

This is the geometry analogue of offline decision-making coverage barriers.

## Required new object: GeometryLearningReceipt

Bind:

```text
training subject hashes
state/transition sampling policy or data generator
success/failure/censored trajectory policy
coverage/support diagnostics
unvisited operator/chart/scale regions
label source (kernel route, solved proof, heuristic, etc.)
gold-route leakage controls
train/dev/fresh-family separation
structural realizability assumptions
OOD/staleness detector
exploration policy for reopening unsupported regions
```

**Rule:** absence of successful trajectories is not evidence of high mathematical distance unless support assumptions justify the inference.

This also prevents a self-confirming feedback loop:

```text
current geometry avoids region
-> region has no successful data
-> learner assigns low value to region
-> geometry avoids it even more
```

Mandatory exploration/coverage challenges remain necessary.
