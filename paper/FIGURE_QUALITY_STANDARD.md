# RAKL Scientific Figure Quality Standard

Status: pre-arXiv and journal figure contract.

## 1. Two figure modes

RAKL paper graphics are split into two non-interchangeable modes.

### Conceptual / formal schematics

Use editable vector source (`TikZ`, SVG, or equivalent). These figures may summarize architecture, state transitions, authority relations or experiment design. They must not contain invented empirical quantities.

### Exact quantitative plots

Use deterministic plotting code from machine-readable source data or result receipts. The plotted values, intervals, sample/cluster units, transformations and exclusions must be traceable to the receipt/source-data artifact. AI image generation is never used to render an exact quantitative panel.

## 2. Claim-first contract

Before drawing any main or Extended Data figure, write:

```text
core scientific conclusion
figure archetype
hero evidence
supporting/robustness evidence
panel-by-panel question
statistics/uncertainty needed
source data identity
reviewer risk
final physical size
```

Every panel must answer a distinct question. If hiding a panel does not weaken the argument, remove or merge it.

## 3. Physical-size and overflow contract

Target layouts:

```text
single column: ~89 mm
full width / two column: ~178 mm
```

At final rendered size:

- target text size >= 7 pt;
- hard floor 5 pt for unavoidable labels;
- no clipped text, equation, marker, confidence interval, legend or panel label;
- no legend covering data;
- no page-edge crop after PDF embedding;
- no `Overfull \hbox`, `Overfull \vbox`, or `Float too large` warning left unresolved in final LaTeX build;
- no stranded heading caused by a deferred float;
- wide/short source figures should be redrawn taller rather than stretched or rotated merely to fill a page.

Final QA requires compile -> render every PDF page -> visual inspection at manuscript size. Source inspection alone is insufficient.

## 4. Data integrity

- Use every registered observation unless a scientific exclusion rule is declared.
- Preserve raw/source data and write exclusions separately.
- For paired or repeated-unit experiments, show paired effects when scientifically relevant rather than relying only on marginal distributions.
- Do not crop axes to exaggerate small effects without a visible reason.
- Do not suppress null or negative generations/panels that are load-bearing for the claim.
- All headline result panels are regenerated from immutable receipt-bound source data.

## 5. Uncertainty and missing data

Every aggregate panel should state or visibly encode:

```text
what the interval/error bar means
sampling/effective cluster unit
n / number of tasks or independent units where relevant
multiplicity or sequential policy for primary families
missing-data/exclusion rule
```

Uncertainty visualization is part of the claim. Avoid encodings that visually convert a wide/ambiguous result into a crisp categorical winner.

## 6. Accessibility and style

- Use a restrained, consistent palette across the paper.
- Never rely on hue alone; combine color with line style, marker, fill pattern, direct labels, or position when identities matter.
- Verify grayscale legibility for the main comparison figures.
- Prefer color-blind-safe cycles for quantitative plots.
- Use the same method/condition identity across every figure.
- Avoid decorative 3D effects, gradients, drop shadows, or pseudo-depth in data panels.
- Prefer direct labels where stable identities make legends unnecessary.
- **Structural arrows and connector paths carry no inline prose labels.** Relation/process wording belongs in separate text blocks, a compact key, tick labels, or the caption. This applies to TikZ `\draw` paths and quantitative callout arrows.
- Avoid annotation arrows in quantitative plots when position, marker, line, or a separate label band can communicate the same event.

Journal-specific Matplotlib style packages such as SciencePlots may be used as presentation helpers, but style cannot change data, statistics, authority or figure logic.

## 7. Exact plot source contract

Every quantitative figure directory should eventually contain:

```text
figure source code
source-data CSV/JSON/Parquet or immutable receipt pointers
README / figure contract
exported PDF/SVG
preview PNG
QA report
```

The source code should record final physical dimensions rather than relying only on arbitrary screen pixel sizes.

For the current V2.1 methods preprint, Figures 5 and 6 are **interim engineering demonstrations** generated by `paper/generate_demo_figures.py` from the frozen pendulum/metrology/archive receipts. They demonstrate implementation semantics and scaling mechanics only. They are not substitutes for the future receipt-bound matched-workflow, self-evolution, or real-science result panels in the journal figure plan.

## 8. Concept schematic contract

Concept figures should expose enough formal structure that a technical reader can map the drawing to the equations. For example:

- Figure 1 must visibly separate proposal generation from evidence-authorized state update.
- Figure 2 must show context-scoped charts, typed transitions and a real obstruction rather than a generic node-link graph.
- The self-evolution figure must show a protected assurance boundary and failed/meta-overfit generations, not a monotone upward arrow.
- The quant application figure must place Polymarket downstream of spot-law validation.

No conceptual figure may hide semantic meaning inside tiny connector labels. Connector geometry communicates structure; semantic interpretation must remain readable as standalone nodes/keys and in the caption.

## 9. Visual review checklist

Before release:

1. render all vector figures on their own;
2. inspect text at the intended physical width;
3. embed in manuscript and rerender all pages;
4. inspect a contact sheet for whitespace, misplaced floats and stranded headings;
5. inspect every figure page at >=150 dpi;
6. verify all panel labels and references;
7. verify bibliography/figure cross-references;
8. search compile logs for overflow/float/undefined-reference warnings;
9. verify no result placeholder enters the public PDF;
10. verify no arrow/connector carries inline text and no quantitative plot uses arrow callouts;
11. repeat after every figure or layout change.

Automated QA is necessary but not sufficient; final visual inspection is mandatory.
